## How this was found, and what it unlocked

This is exactly the shape the head's mid-round broadcast flagged: a small
`lui/addiu %hi+%lo` + `jr $ra` function returning `&D_xxxxxxxx`. Running
`tools/classtable.py D_80086668` (and, from the sibling table found the same
way, `tools/classtable.py D_800865C8`) before writing any other C in this
unit showed:

- Both tables are near-identical siblings (same slot values at nearly every
  offset), confirming a shared parent/child relationship independent of this
  unit's OWN main class (`D_800866E8`, resolved via `func_8004D244`, a
  DIFFERENT accessor living in `class_3bb8c`).
- `func_8004A478` (this unit, also matched) occupies +0x070 of both tables
  identically -- that is what let it be typed as a method of THIS sibling
  class rather than guessed at with raw offsets.

So yes, the "getter returning &D_xxx, `classtable.py` it before doing
anything else" move applies to this unit, and it's what resolved
`func_8004A478`'s own struct shape (see `docs/match-reports/func_8004A478.md`).
It did NOT, however, resolve this unit's MAIN class (`D_800866E8`) -- that
table's own accessor, `func_8004D244`, is not a function this unit owns (it
lives in `class_3bb8c`, found by grepping for `D_800866E8`'s address across
`asm/`, not by a local getter call).
