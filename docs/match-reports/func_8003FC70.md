# func_8003FC70 -- STALL (rodata segmentation, NOT a codegen problem)

> **HEAD CORRECTION, round 14.** Filed as a 35/35 MATCH. The C is believed
> correct and its own text does compare clean -- but **merging it turns the
> whole image 1707 bytes off**, so it cannot stand as a match and has been
> restored to `INCLUDE_ASM` with the body preserved in `#if 0`.
>
> **The mechanism is rodata migration, and it is a new Gate 2 constraint.**
> This function owns `D_80011194`, which lives in rodata slot `0x1908` --
> a slot that had to be ATTACHED to `code_2cc8c_e` at carve time so that
> `func_8003FB1C`'s jump table could resolve its unit-local `.L` labels.
> With `migrate_rodata_to_functions: True`:
>
> - while `func_8003FC70` is `INCLUDE_ASM`, splat migrates `D_80011194`
>   into that function's own generated `.s`, and the layout is retail's;
> - once it is C, there is no generated `.s` to migrate into, the symbol is
>   emitted elsewhere, and everything after it in rodata shifts.
>
> **So a function that owns rodata inside an ATTACHED slot cannot be matched
> to C while the slot stays attached.** The two are mutually exclusive, and
> nothing warns you: the function's own bytes look right, and the damage
> appears as a whole-image diff starting in RODATA, thousands of bytes before
> any of the unit's text.
>
> Diagnosed by reverting this one function to `INCLUDE_ASM` and watching
> 1707 -> 0, after first proving the merged header innocent by reverting the
> unit's code to its carve state (also 0).
>
> **The way out, for whoever wants this match:** re-segment so `D_80011194`
> is NOT in the attached part of the slot. The attach only exists for
> `jtbl_80011108`, whose owner `func_8003FB1C` is `addiu-$at` blocked and
> will therefore never become C -- so the jump table is safe to attach
> forever, and `D_80011194` should sit in a standalone slot beside it. A
> first attempt at that split (boundary `0x1994`) made things far worse
> (339541 bytes), so the boundary needs care -- likely an alignment
> constraint on where a rodata section may begin. That is the open lead.

## Shape notes

- Written with explicit `goto`s to reproduce retail's exact block layout
  (a nested `if (mode==1) / if (mode<2) {if(mode==0)... else...} / if
  (mode==2) / if (mode==3) / else` chain with two blocks -- `set:` and
  `err:` -- each reached from more than one place) rather than a `switch`,
  because a `switch` risked GCC choosing its own jump-table-or-branch
  lowering for this dense a case set (0-3) instead of retail's literal
  branch chain.
- The retail string literal (`"not supported light mode %d\n"`, previously
  named `D_80011194` in the disassembly) is written as an ordinary C string
  literal rather than a separate declared global -- the compiler emits its
  own rodata for it, and it lands at the same address once the surrounding
  code matches byte-for-byte.
- `func_80012C20` (Psy-Q printf-like, `asm/psyq_2258.s`) already has an
  extern in `include/code_8220.h` for a DIFFERENT call site's arity (fmt +
  2 args). Declared a second, independent local extern here with THIS call
  site's own arity (fmt + 1 vararg) rather than reusing/widening the
  existing one -- same "declare locally per call site" convention already
  used for other variadic-looking Psy-Q calls in this project.
