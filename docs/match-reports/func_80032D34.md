## Why this one was not attempted

`func_80033C90` (202 words, one-fifth this size) already showed that
getting GCC 2.6.3's register/stack allocation to match retail exactly, on
a body with several live values surviving multiple calls, resists
straightforward source restructuring and costs many iterations for a
partial payoff (see `func_80033C90.md`: 3 structural variants, best
18/202, all logically correct). This function has MORE live state (7
callee-saved registers: s0-s6), a 256-word local buffer, two internal
loops, and 4 distinct function calls whose own signatures are not yet
established elsewhere in the codebase. Attempting a full byte-exact
reconstruction was judged not to fit the remaining session budget
alongside the two already-attempted functions in this unit; the value
left here is getting the ALGORITHM right and written down so the next
attempt doesn't have to re-derive it from raw hex.

## Signature (established, high confidence)

```c
s16 func_80032D34(void *a0, s16 a1, s32 a2, s32 a3)
```

Fixed independently by two existing call sites already in the tree:
`code_179d8_i.c`'s own `func_80032D00`: `return func_80032D34(a0, a1, 1,
a2);`, and `code_179d8_c.c`: `func_80032D34(a0, a1, 0, 0)` /
`func_80032D34(a0, a1, 1, a2)`. `a0` is a VAB header pointer (see below);
`a1` is a requested VAB slot id, or `-1` for "pick any free slot"; `a2`
is a mode flag (0 = allocate sample RAM automatically, 1 = the caller has
already reserved it at `a3`); `a3` is either unused (mode 0) or the
caller-supplied RAM pointer (mode 1). This is a **`SsVabOpen`-family**
function — the register-level structure of "validate, claim a slot,
parse a VAB header, walk its program/tone tables, size and place its
sample data, roll back on any failure" matches the real PsyQ
`SsVabOpen`/`SsVabOpenHead` semantics, though as with `SsUtGetVabHdr`/
`func_80033260` earlier in this unit, this is almost certainly the
game's OWN reimplementation, not a call into the SDK.
