Unit `libsnd_vmanager`, round 21 (2026-09-06). Sibling of `func_80030864`
(see that report for the shared family writeup) -- the "setter" shape:
writes `(u8)p2` to `_svm_pg[p1].unk1`, then RE-READS and returns the
stored byte (retail reloads the `_svm_pg` global pointer a second
time before the read-back rather than reusing the address it just
computed for the store -- write it as two separate statements, not a
cached-and-returned assignment, or the reload disappears).

```c
extern s32 func_80032148(s16 a0, s16 a1);
extern SlotE968 *_svm_pg;   /* see func_80030864.md for the typedef */

s32 func_800307F0(s16 p0, s16 p1, s32 p2)
{
    if (func_80032148(p0, p1) != 0)
        return -1;
    _svm_pg[p1].unk1 = (u8) p2;
    return _svm_pg[p1].unk1;
}
```

`p2` (the value to store) gets none of the usual s16/u16 prologue
narrowing idiom -- retail passes it straight through in `$a2`/`$s1` with
no `sll`/`sra` or `andi` at entry, only truncated implicitly by the
`sb`/`sw` store width. That is why it is typed `s32` here rather than
`u8`: a narrower parameter type would trigger the (absent) prologue
truncation and cost a word.

Matched first try once `func_80030864`'s shape was established.

### Proposed learning

**A "write field, then re-read the same field to return it" setter
shape reloads the base pointer a second time in retail** -- write the
store and the return as two separate statements against the indexed
expression, not `return field = value;`, to reproduce the second
`lui`/`lw` of the global.
