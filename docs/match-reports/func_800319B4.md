Two residues found and fixed, both worth recording generally (neither is
new, but this is a second confirming instance of each):

1. **The 4th register parameter (`p3`) is unused**, same "silent ABI
   waste" idiom as `func_800302DC` in this same unit -- the 5th
   parameter (`p4`) arrives on the stack at `0x40($sp)` (post-frame),
   which only lines up if there really are 4 register parameters ahead
   of it despite the body never touching `$a3`.

2. **A stack-passed parameter's declared width changes which load
   instruction retail uses, and this is NOT the same rule as a
   register-passed parameter's prologue-narrowing idiom.** First attempt
   declared `p4` as `s16`; that produced `lw` (full word) + `sll`/`sra`
   (3 instructions, +2 words) at the read site, because a *signed*
   narrow stack argument gets the same "avoid `lh`, use `lw` + manual
   sign-extend" treatment this target applies everywhere else. Retail's
   actual instruction is a single `lhu $s3, 0x40($sp)` with no further
   extension at all before the value is reused -- that only comes from
   an **unsigned** narrow type (`u16`), where a straight `lhu` already
   *is* the correct value and needs no extra widening pass. Changing
   `p4` from `s16` to `u16` fixed the size and the register allocation
   in one step (2 attempts: wrong-type build, then the fix).

3. Consequently `func_8002F3E8`'s last parameter is also typed `u16`
   here to match the call site's exact register content (no extra
   masking applied when passing `p4` straight through).

4. **The final `ret == 0 ? -1 : 0` boolean collapses to branchless
   `sll`/`sltiu`/`negu` only when the callee's return type is `s16`.**
   With the callee declared to return `s32`, the comparison against 0
   didn't need the `sll v0,v0,0x10` widening step retail has, and the
   word count came up one short. Declaring `func_8002F3E8`'s return type
   `s16` (matching the "signed 16-bit value needs widening before a
   32-bit-wide comparison" rule already documented for parameters)
   reproduced the exact `sll`/`sltiu`/`negu` triplet with a plain
   `if (callee(...) == 0) return -1; return 0;` -- no explicit
   `-(x==0)` arithmetic needed in the source.

### Proposed learning

**The "avoid `lh`, use full-word-load-plus-manual-sign-extend" idiom
this target applies to signed narrow reads is scoped to how the value's
declared type is SIGNED, not to whether it is register- or
stack-passed.** An unsigned narrow stack argument still compiles to a
plain `lhu` with no follow-up widening. Already known for register
arguments (the `andi` vs `sll`/`sra` split); this is the same rule
holding across the stack-argument boundary too, worth having recorded
in one place since a `lw`+`sll`+`sra` where retail has one `lhu` reads,
at first glance, like a completely different bug (extra register
promoted to callee-saved) rather than one wrong type qualifier.
