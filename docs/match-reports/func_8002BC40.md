## The reading that mattered: two symbols, one array

The disassembly names two globals, `D_8008B9F4` and `D_8008B9FC`, each with
its own `lui`/`addiu` materialisation, and both advance by 0x2C per iteration.
They are **one object**: `0x8008B9FC - 0x8008B9F4 = 8`, which is the `name`
member's offset, folded into the symbol at compile time.

What made it read as two independent bases is that GCC treats the two accessed
members differently, and the difference is mechanical rather than semantic:

- `.id` is only ever *tested*, so it is emitted in the indexed-global form
  (`lui $at` / `addiu $at` / `addu $at, $at, $s1` / `lw $v0, 0($at)`) and needs
  no register live across the loop -- hence the base is re-materialised every
  iteration, inside the loop.
- `.name`'s ADDRESS is passed as an argument, so it must be a real value in a
  register. Loop strength reduction turns it into the induction variable `$s2`,
  initialised to `D_8008B9F4 + 8` and bumped by 0x2C.

So **one `for` loop over one array produces two induction variables and two
base materialisations.** Writing it as a separate source pointer would have
been the natural inference from the register picture and it is not needed.

This is the same discriminator round 23 adjudicated for
`_svm_sreg_buf`/`D_8008D7F2` in `SsUtSetDetVVol`, reached from the opposite
direction: there, a shared base with a `+2` fold proved one object; here,
*separate* bases do NOT prove two, because "each member gets its own
`lui`/`addiu`" measures how GCC chose to hold each access, not whether the
symbols are one object. Both readings emitted identical bytes there; here only
the one-array reading was tried, and it matched first attempt.

The single `lw` feeding both the `== 0` and the `== id` compares is ordinary
CSE and needs nothing in source.

### Proposed learning

**Separate `lui`/`addiu` materialisations for two globals 8 bytes apart with a
common stride are ONE array, not two objects -- and the split is explained by
what each member is USED for, not by the source.** A member that is only
tested gets the indexed-global form and re-materialises its base inside the
loop; a member whose address is passed to a call gets strength-reduced into a
live induction variable. Read the stride first: a common non-power-of-two
stride on both symbols is the tell, because it means one `sizeof`.

This is the converse half of round 23's `SsUtSetDetVVol` adjudication, which
established that a shared base with a small positive fold is conclusive FOR
one object. The pair now covers both directions: shared base proves one
object; separate bases prove nothing either way.
