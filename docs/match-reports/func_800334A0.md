## Summary

Builds a small command struct on the stack (opcode `3`, then two `s16`
fields each computed as `arg * 129`) and passes its address to
`func_8003760C` (uncarved, lives in `psyq_SpuSetMute.s`). Two attempts, one
stack-size residue.

    s.unk4 = a0 * 129;

`a0 * 129` (`= a0 * 128 + a0`, i.e. `(a0<<7)+a0`) is GCC's own strength
reduction of a plain multiply -- written as literal `* 129` in source, no
manual shift needed.

## One residue: struct too small, wrong frame size

First pass declared only the 8 touched bytes (`unk0`/`unk4`/`unk6`, no
trailing padding). That compiles and produces the right FIELD writes, but
the local's total size drives the stack frame allocation, and an
undersized struct gives `addiu $sp,$sp,-0x20` where retail has `-0x40` --
16/20 words match, with the frame-size instructions (the initial `addiu`,
the `$ra` save/restore offsets, and the final `addiu`) all off by a
constant. `funcdiff.py` flagged this immediately as four scattered
word-level diffs at the frame-touching instructions specifically, not a
diffuse mismatch.

Every wrapper matched so far in this unit reserves exactly `0x10` bytes at
the bottom of its frame regardless of how few argument words it actually
uses (visible on the smallest ones, e.g. `func_80032D00`'s `-0x18` frame is
`0x10` (unused arg-spill reservation) + `0x8` (`$ra`, rounded up) with zero
locals) -- a fixed per-call convention, not something tied to this
function's own argument count. Retail's `0x40` frame is therefore `0x10`
(the same reservation) + the struct + `0x8` (`$ra`), which back-solves to a
`0x28`-byte struct: `0x28` bytes actually reserved for the local, of which
only the first `8` are ever written by this call site (the rest presumably
belongs to fields a fuller Ss-command struct has that this particular
opcode-`3` construction leaves uninitialized). Padding the struct out to
`0x28` bytes total reproduced the exact frame on the next attempt.

### Proposed learning

**A stack-resident local struct's compiled size is measured from the
frame, not read off the fields the function happens to touch.** When only
some prefix of a struct is written at a given call site but the surrounding
`addiu $sp` frame size implies a bigger local, back-solve the struct size
from the frame arithmetic (`frame_size - fixed_arg_spill(0x10) -
rounded_ra_save(0x8)` in this project's convention) and pad the struct out
with trailing `u8 padN[...]` to match, rather than trusting the touched
byte range as the struct's true extent. This project's function-call
convention reserves a constant `0x10`-byte argument-spill area at the
bottom of every frame regardless of actual argument count, which is what
makes the back-solve arithmetic reliable -- confirmed against
`func_80032D00`'s zero-local `0x18` frame (`0x10 + 0x8`, no struct at all).
