`extern short SsUtGetVagAtr (short, short, short, VagAtr*);`. Same evidence
pattern as `SsUtGetVabHdr` immediately above it in the same file (also
identified from a `LIBSND.H` struct match): the function copies exactly
`VagAtr`'s non-reserved fields — skips `reserved1`/`reserved2` at offsets

uppercase `SYS/TYPES.H` exists). A local copy of the same 0x20-byte layout

## Signature

```c
short func_80033260(short vabId, short prog, s32 tone, VagAtr *vagatr)
```

The third parameter (`tone`) is **not** sign-extended on function entry,
unlike the first two (`vabId`, `prog`, each get an `sll 16`/`sra 16` pair
before use). It is only ever used inside `tone + (D_8008EA13 << 4)`, whose
result is truncated to 16 bits anyway by the later index-scale idiom
(`sll $v1,16` / `sra $v1,11`, net `(s16)(sum) * 32` — `sizeof(VagAtr) == 32`).
Because the truncation happens downstream regardless, the retail source
evidently declared this parameter wider than the SDK's `short` prototype
(here typed `s32`), and the compiler had no correctness reason to narrow it
on entry. This is a measured asymmetry, not a guess: matching required
leaving it un-narrowed — an `s16 tone` parameter reintroduces an early
sign-extension the retail bytes do not have.

## Control-flow shape mattered

An `if (cond != 1) return -1;` / fallthrough-success first draft scored
19/144 with the very first branch instruction already wrong (retail
`beq $v1,$v0,.L...` vs built `bne`-shaped code) — GCC 2.6.3 does not treat
`if (x) return; else {...}` and `if (!x) {...} return;` as interchangeable
at this optimization level for this shape. Rewriting to
`if (_svm_vab_used[vabId] == 1) { ...success...; return 0; } return -1;` —
mirroring retail's own beq-to-success / fallthrough-to-`-1` layout exactly —
matched immediately.

## Proposed learning

For a `VagAtr`-shaped SDK sound-utility function (or any early-out gate
`if (flag[x] == N) { body; return 0; } return -1;`), write the early-out in
the SAME branch sense as the retail beq/bne, not the logically-equivalent
inverted sense — GCC 2.6.3 -O2 is not guaranteed to normalize the two to
identical code, and doing so cost one full iteration here.
