## What it computes: SPU voice-descriptor init / "key on" for `D_8008E9D0` channels

For `i` in `0 .. D_8008E9D0-1` (a small channel/voice count), the function:

1. Resets a 0x34-stride channel-configuration record (the SAME shared
   family `code_179d8_j.c`/`code_179d8_m.c` already document as
   `Rec34D994`/`Rec34Half`/`Rec34Byte`) to a set of constants: `D_8008D98A`
   (0x18), `D_8008D988` (0xFF), `D_8008D9A3` (0), `D_8008D98C` (0),
   `D_8008D98E` (0), `D_8008D996` (0xFF), `D_8008D998` (0), `D_8008D99A`
   (0), `D_8008D99C` (0xFF).
2. Initializes a 0x10-byte-stride record via a POINTER `D_8006DAD4`
   (loaded fresh each iteration, not an array base) at offsets +0x6/+0x4/
   +0x8/+0x0/+0x2/+0xA to `0x200`/`0x1000`/`0x80FF`/`0`/`0`/`0x4000`. Same
   global `code_179d8_m.c` reads through a DIFFERENT, fixed-offset object
   view (`ObjDAD4`, offsets 0x194/0x196) — this function's own reading, a
   16-byte-stride per-channel record, is a third independent view of the
   same symbol, all valid per the project's multiple-local-views
   convention.
3. Stores `i` into `D_8008EA26` (a `volatile u16` — `code_179d8_m.c`'s own
   comment on this exact symbol explains why: "written as a side effect,
   then re-read from the global... genuinely needs volatile"), re-reads
   it, and computes a bit position/mask (`1 << (i & 0xF)` into the low
   16-voice group, or `1 << ((i-16) & 0xF)` into the high 16-voice group).
4. Re-clears `D_8008D9A3[i]` a SECOND time (same field zeroed in step 1)
   with the SAME value (0) — a genuinely duplicated write, not a
   misreading; confirmed present in retail's own instructions twice.
5. Updates two PS1-SPU-shaped 16-bit register pairs, `D_80090C60`/
   `D_8008E228` (voices 0-15) and `D_80090C64`/`D_8008E22C` (voices
   16-31): ORs the new bit into the hardware-mirrored "key on" register
   and CLEARS the same bit from a software "still fading"/"gate" mask —
   i.e. this is PS1 SPU voice key-on with a software status mirror kept
   in sync.
6. Loops while `i < D_8008E9D0`.

 * This function's own local view of the shared 0x34-stride channel-
 * configuration record family that code_179d8_j.c/code_179d8_m.c already
 * document (Rec34D994/Rec34Half/Rec34Byte there) -- kept LOCAL per the
 * project's multiple-independent-local-views convention, not a shared
 * header. Every symbol here is 0x34 bytes from its neighbor; only the
 * one field this function writes is named per symbol.
 */
typedef struct {
    u16 unk0; /* +0x0 */
    u8 pad2[0x34 - 0x2];
} Rec34U16;
extern Rec34U16 D_8008D988[];
extern Rec34U16 D_8008D98A[];
extern Rec34U16 D_8008D98C[];
extern Rec34U16 D_8008D98E[];
extern Rec34U16 D_8008D996[];
extern Rec34U16 D_8008D998[];
extern Rec34U16 D_8008D99A[];
extern Rec34U16 D_8008D99C[];

typedef struct {
    u8 unk0; /* +0x0 */
    u8 pad1[0x34 - 0x1];
} Rec34U8;
extern Rec34U8 D_8008D9A3[];

/* code_179d8_m.c's own comment on this exact symbol: "written as a side
 * effect, then re-read from the global (not a cached register) a few
 * instructions later... Genuinely needs volatile: without it, this
 * compiler proves... the re-read is redundant and elides it entirely."
 * Independently re-confirmed here: the same store-then-reload shape shows
 * up in this function's own disassembly. */
extern volatile u16 D_8008EA26;

/* "Loop bound / threshold" -- code_179d8_m.c's own comment on this symbol. */
extern u8 D_8008E9D0;

/*
 * This function's OWN reading of D_8006DAD4: a POINTER VARIABLE (loaded
 * with `lw`, not an array base) to a 0x10-byte-stride record, indexed by
 * channel. code_179d8_m.c reads the SAME symbol as a fixed-offset object
 * pointer (its own ObjDAD4, offsets 0x194/0x196) -- a different, valid
 * reading per the project's convention: same global, two shapes, two
 * independent local views.
 */
typedef struct {
    u16 f0;  /* +0x0 */
    u16 f2;  /* +0x2 */
    u16 f4;  /* +0x4 */
    u16 f6;  /* +0x6 */
    u16 f8;  /* +0x8 */
    u16 fA;  /* +0xA */
    u8 pad[0x10 - 0xC];
} Rec16DAD4;
extern Rec16DAD4 *D_8006DAD4;

/* PS1 SPU voice key-on/off pair, split low/high across two 16-bit halves
 * (voices 0-15 / 16-31) -- D_80090C60/64 are the hardware-mirrored "just
 * keyed on" mask, D_8008E228/22C a software mask this function clears the
 * same bit from (a "no longer fading out" bookkeeping flag). */
extern u16 D_80090C60;
extern u16 D_80090C64;
extern u16 D_8008E228;
extern u16 D_8008E22C;

void func_80031F3C(void)
{
    s16 i;
    u16 bitpos;
    u32 bitLo;
    u32 bitHi;
    u16 hw0;
    u16 hw1;
    u16 mask0;
    u16 mask1;

    if (D_8008E9D0 == 0) {
        return;
    }

    i = 0;
    for (;;) {
        D_8008D98A[i].unk0 = 0x18;
        D_8008D988[i].unk0 = 0xFF;
        D_8008D9A3[i].unk0 = 0;
        D_8008D98C[i].unk0 = 0;
        D_8008D98E[i].unk0 = 0;
        D_8008D996[i].unk0 = 0xFF;
        D_8008D998[i].unk0 = 0;
        D_8008D99A[i].unk0 = 0;
        D_8008D99C[i].unk0 = 0xFF;

        D_8006DAD4[i].f6 = 0x200;
        D_8006DAD4[i].f4 = 0x1000;
        D_8006DAD4[i].f8 = 0x80FF;
        D_8006DAD4[i].f0 = 0;
        D_8006DAD4[i].f2 = 0;
        D_8006DAD4[i].fA = 0x4000;

        D_8008EA26 = i;
        bitpos = D_8008EA26 & 0xFFFF;
        if (bitpos < 0x10) {
            bitLo = 1u << bitpos;
            bitHi = 0;
        } else {
            bitLo = 0;
            bitHi = 1u << (bitpos - 0x10);
        }

        i++;
        D_8008D9A3[bitpos & 0xFFFF].unk0 = 0;

        hw0 = D_80090C60;
        hw1 = D_80090C64;
        mask0 = D_8008E228;
        hw0 = (u16)(bitLo | hw0);
        D_80090C60 = hw0;
        mask0 = mask0 & (u16) ~hw0;
        D_8008E228 = mask0;

        mask1 = D_8008E22C;
        hw1 = (u16)(bitHi | hw1);
        D_80090C64 = hw1;
        mask1 = mask1 & (u16) ~hw1;
        D_8008E22C = mask1;

        if (!(i < D_8008E9D0)) {
            break;
        }
    }
}

## Residue: the "split scaled index" eager multiply for `D_8006DAD4`, still open

This function touches the SAME `D_8006DAD4` global the carve comment
flagged as sharing `DECOMPILATION_LEARNINGS.md`'s "split scaled index"
idiom (`code_179d8_m`/`code_179d8_j`'s `func_8002EDD4` derivation: `u16
woff = (u16)i * 8;` computed eagerly, then `((s16*)base)[woff+N]`). Retail
computes the per-channel offset into `D_6DAD4` via a SPLIT shift:

```
sll a0, a0, 0x13      # a0 = i << 19  -- computed EARLY, right after the
                       # 0x34-stride index (v0=i*0x34), BEFORE any of the
                       # nine stride-field stores
... nine 0x34-stride field stores, using v0 ...
lw  v0, D_6DAD4         # base pointer, loaded LAST (matches the idiom)
sra a0, a0, 0xf         # a0 = (i<<19)>>15 = i*16  -- completed LATE,
                        # right before first use
addu a0, a0, v0
sh  ..., 6(a0) / 4(a0) / 8(a0) / 0(a0) / 2(a0) / 0xA(a0)
```

**Three spellings tried, none reproduces this exactly:**

1. `D_8006DAD4[i].fN` (struct indexing, `Rec16DAD4` with stride 0x10) —
   the shape used in the body above. Compiles the index as a plain `sll
   a0, a0, 0x4` computed LATE (right where used, after the base-pointer
   load), not the early `sll .. 0x13` / late `sra .. 0xf` split. Same
   numeric result, different instruction sequence — 1 word short here
   alone (the `sll .. 0x13` is simply absent).
2. `u16 woff = (u16)i * 8;` (the exact documented idiom spelling, eager,
   first statement of the loop body) with `D_8006DAD4` re-typed as `u16
   *` and accessed `D_8006DAD4[woff+N]` — produces an `andi`+`sll 3`
   pair instead of the `sll 0x13`/`sra 0xf` pair, and ALSO moves the
   0x34-stride index computation onto a SEPARATE register (`v1`) instead
   of reusing the same `a0` retail reuses for both. Worse (5/131).
3. `s32 shifted = ((s32)i << 19) >> 15;` computed as ONE eager statement
   right after the first stride write, then used via
   `*(u16*)((u8*)D_8006DAD4 + shifted + N)` — DOES reproduce the exact
   `sll a0,a0,0x13` instruction in the right position, but the SUBSEQUENT
   `lw v0,D_6DAD4` (the base-pointer load) also moves EARLY with it
   (right after the `shifted` computation), whereas retail keeps that
   load LATE, immediately before first use. The visible shift instruction
   and the base-pointer load are evidently two INDEPENDENT halves in
   retail's compiled output that a single eager C statement recombines
   into one unit here. Worse overall (18/131) despite fixing the one
   instruction it targeted, because moving the load early perturbs
   several unrelated things downstream (the SPU-register-pair read order
   later in the function).

**Not resolved: no construct tried gets the `sll .. 0x13` instruction into
the right POSITION while also keeping the `D_6DAD4` pointer LOAD in
retail's late position.** This may need the SAME two-phase split the
"split scaled index" doc's own idiom describes but literally written as a
single statement that the compiler nonetheless partially schedules early —
worth another pass with `tools/asm-differ/diff.py --debug`-style
inspection or the permuter (not attempted this session; time budget spent
elsewhere).

### Proposed learning

**The "split scaled index" idiom's eager half and the base-pointer LOAD
appear to be two independently-scheduled things in this compiler, not one
atomic unit** — reproducing the eager shift exactly (attempt 3 above) does
NOT guarantee the base-pointer load stays late; a single C statement that
computes the full offset gives the compiler license to fold the load in
with it. If a future attempt on this idiom family hits the same "got the
shift, lost the late load" trade-off, that is this same mechanism, not a
regression from something else.
