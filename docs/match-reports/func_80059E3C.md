### Proposed learning

A loaded struct field used ONLY as a branch condition (no arithmetic, no
further use of the value) can land in an argument register (`$a1`, `$a2`,
...) in retail even when nothing in the surrounding code obviously needs
that register for an argument -- speculatively, GCC 2.6.3's register
allocator may prefer an argument register here simply because it's
otherwise unused in this basic block, not because of any source-visible
reason. This makes the choice effectively unreachable from source reshaping
(4 independent attempts, including a scheduling barrier, all failed to move
it) -- treat "condition-only field load lands in an unexpected register" as
a stall signal early rather than a prompt to keep restructuring.
