This compiled clean (`build exit=2`, no compile-error grep hit) but scored
only 18/67, with the divergence starting at word 11 — retail's `beq`
(branch-if-equal, jumping FORWARD into the success body) came out as a
`bne` in the built object, and every word from the success body onward
drifted by one position. **Branch polarity changed which block physically
sits first**, which is a length/layout change, not a byte-for-byte
resequencing — funcdiff's raw diff looked like uniform drift rather than a
handful of substitutions, which is itself informative: a real polarity
flip shows as "everything after the branch is offset," not as scattered
single-word diffs.

Flipping to `if (cond) { success; return 0; } return -1;` (branch-if-equal
to the success body, unconditional fail path immediately after the guard)
matched immediately, word-for-word.

### Proposed learning

**Branch polarity is a first-class thing to try before reshaping anything
else, and its failure signature is distinctive: a near-total drift starting
right after the guard, not scattered single-word diffs.** When a function's
retail disassembly branches on the SUCCESS condition into the main body
(rather than branching on the failure condition to an early return), write
the C to match that shape (`if (success) { ...; return good; } return bad;`)
rather than the more idiomatic-looking early-return guard clause — they are
not guaranteed to compile to the same bytes even though they're logically
identical, and here they clearly didn't.
