The pinned pipeline FOLDS the address computation maspsx sees from cc1
(`lui $at` / `addu $at,$at,$reg` / `lw ...%lo(...)($at)` -- three
instructions) where retail has the UNFOLDED four. The fold happens in
maspsx, BELOW cc1, and there is no source form that suppresses it.
See `docs/research/addiu-at-blocker.md`; the flag inside it
(`nop_mflo_mfhi`) is the right MECHANISM at the wrong GRANULARITY, which
sharpens the blocker without resolving it. Operator's call, and not
something to experiment with mid-round.

**A `%lo(jtbl_*)` hit counts.** A dense `switch` is blocked exactly like
an indexed global: cc1 emits the same generic pseudo-op for both and
expresses no opinion on addressing, so maspsx cannot tell a code address
from a data one and does not try. Round 10 "corrected" this grep to
exclude `jtbl_` and had to retract it -- see CLAUDE.md's screen section.

## This function is why the carve needed a rodata split

`func_80032588` owns `jtbl_80010CD8`, which lived in the standalone
rodata slot at `0xFD8`. Its words are `.L` labels local to this function's
own `.s`, which a standalone rodata object cannot see, so the sub-slot is
ATTACHED to `code_179d8_c` in the splat yaml.

The attach is required even though this function stays `INCLUDE_ASM` --
being `INCLUDE_ASM` assembles the text, it does not embed the table. The
`0xFD8` slot is shared by every slice of the old `code_179d8` monolith, so
it was split at the ownership boundary rather than attached whole: an
attached slot's symbols migrate into the owning unit's functions, and a
symbol referenced only from elsewhere would drop out of the link.

No C was written and no score was measured. The screen was run at Gate 1,
before the unit was offered to a runner, so no attempt budget was spent
discovering this -- which is the point of screening: a blocker that only
surfaces after you have understood the function is not bounded by the
30-attempt cap.
