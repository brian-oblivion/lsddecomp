## Note for whoever revisits this (not this round's job, but observed in passing)

At 86 instructions this is also, by a wide margin, the most expensive
function in this unit's original queue — bigger than the next-largest
(`func_8003CC2C` at 44) by a factor of two. If the `addiu_at` blocker is ever
lifted, this is not a "quick recheck": its jump table alone has 14 entries
and several of its case blocks share a common re-dispatch tail keyed on the
same `a1` value the jump table already consumed (see "What it does" above),
which is exactly the kind of GCC 2.6.3 case-density/pivot-order behaviour
CLAUDE.md's switch guidance warns not to transcribe by observed comparison
order. Budget it as a full fresh derivation, not a one-line unblock.

### Proposed learning

Same as `func_8003C48C`'s report: `addiu $at, $at, %lo(...)` blocks dense
switches lowered to a jump table exactly as it blocks an indexed data-global
load — the `jtbl_*` vs. `D_*` symbol name is not a valid discriminator. Two
data points from one unit (`func_8003C48C`, this function) is a small sample,
but both are switches over a byte/word-ish message code with double-digit
case counts, which is exactly the code shape (`code_2cc8c` was carved
specifically as "switch dispatchers over a small event/message code") most
likely to recur elsewhere in this executable. Screen every dense `switch`
candidate for this blocker before attempting it, regardless of whether the
`%lo` symbol looks like a jump table or a data global.
