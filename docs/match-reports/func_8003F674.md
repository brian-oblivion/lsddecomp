## Branch polarity residue, and the fix

First attempt wrote the natural reading `if (shift < 0x10) { copy } else {
shift }`. That put the COPY block as the physical fallthrough and the SHIFT
block as the branch target -- the opposite of retail's layout (retail falls
through into the shift path and branches forward into the copy path). Flipping
the guard to `if (shift >= 0x10)` (logically identical, opposite polarity)
reproduced retail's layout exactly, matching the project's existing "branch
polarity is a real, separate residue from branch targets" lesson
(DECOMPILATION_LEARNINGS, round 13).
