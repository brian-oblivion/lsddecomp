# func_800195EC — MATCHED (58/58 words), as C over the GTE macros

Unit: `src/code_8220_b.c`. GTE transform/clip/OT-bucket routine: runs `rtpt`
on the three vertices the caller loaded with `gte_ldv3`, checks the FLAG
register, runs `nclip` (backface cull) and `avsz3` (Z average for the
ordering table), and on success caches the three screen coordinates and
stores `&otBase[otz >> otShift]` into the context. Returns `0` on success,
`1` when culled.

Two callers, both in this unit: `func_800193C0` (triangles) and
`func_800194A4` (quads, which then transform the fourth vertex with
`gte_ldv0`/`gte_rtps`).

Round 13's report asserted "No C form is possible for `rtpt`/`nclip`/
`avsz3`/`cfc2`". That was true of the INSTRUCTIONS and false of the
FUNCTION: each instruction is the body of a Psy-Q `gte_*` macro, the game's
source called those macros, and the surrounding code is C that GCC compiled
normally. The disassembly said so directly — retail's flag test is the
`gte_stflg` macro body verbatim (`cfc2 $12,$31; addi $13,$zero,4;
sll $13,$13,16; and $12,$12,$13; sw $12,0(reg)`), preceded by an
`addiu $2, $5, 0x5c` that is GCC computing `&ctx->flag` for the macro's
`%0` operand. Nothing in the function is handwritten.

## Final source

`include/gte.h` gained `gte_rtpt`, `gte_nclip`, `gte_avsz3`, `gte_stflg`,
`gte_stopz`, `gte_stdp`, `gte_stotz` and the three-pointer `gte_stsxy3`
for this function; names follow `include/psyq/INLINE.H`, COP2 register
numbers were cross-checked against `include/psyq/GTENOM.H` (`read_opz` =
r24, `read_p` = r8, `read_otz` = r7, `read_flag` = cfc2 r31).

```c
#include "gte.h"

typedef struct GteCullCtx {
    /* +0x000 */ u32 *otBase;        /* ordering table, 4-byte entries */
    /* +0x004 */ s32 otShift;        /* otz >> otShift indexes otBase */
    u8 pad008[0x014 - 0x008];
    /* +0x014 */ u8 unk14;           /* copied to the owner's byte at +0x3 */
    u8 pad015[0x020 - 0x015];
    /* +0x020 */ s32 otz;            /* avsz3 result */
    /* +0x024 */ s32 dp;             /* IR0, the depth-cue factor */
    /* +0x028 */ s32 opz;            /* nclip result (MAC0) */
    u8 pad02C[0x030 - 0x02C];
    /* +0x030 */ u32 *otSlot;        /* &otBase[otz >> otShift] */
    u8 pad034[0x05C - 0x034];
    /* +0x05C */ s32 flag;           /* GTE FLAG & 0x40000 */
    /* +0x060 */ s32 sxy0;
    /* +0x064 */ s32 sxy1;
    /* +0x068 */ s32 sxy2;
    u8 pad06C[0x078 - 0x06C];
    /* +0x078 */ s32 saturated;      /* set when the transform saturated */
} GteCullCtx;

typedef struct GteCullOwner {
    u8 pad000[3];
    /* +0x003 */ u8 unk3;
} GteCullOwner;

s32 func_800195EC(void *arg0, void *arg1)
{
    GteCullOwner *owner = arg0;
    GteCullCtx *ctx = arg1;

    ctx->saturated = 0;
    gte_rtpt();
    owner->unk3 = ctx->unk14;
    gte_stflg(&ctx->flag);
    if (ctx->flag != 0) {
        if (ctx->flag != 0x40000) {
            return 1;
        }
        ctx->saturated = 1;
    }
    gte_nclip();
    gte_stopz(&ctx->opz);
    if (ctx->opz <= 0) {
        return 1;
    }
    gte_stdp(&ctx->dp);
    if (ctx->dp >= 0x1000) {
        return 1;
    }
    gte_avsz3();
    gte_stotz(&ctx->otz);
    gte_stsxy3(&ctx->sxy0, &ctx->sxy1, &ctx->sxy2);
    ctx->otSlot = &ctx->otBase[ctx->otz >> ctx->otShift];
    return 0;
}
```

The signature stays `(void *, void *)` because the header declares it that
way for the two callers, which still address the same object by offset; the
struct views are local to the `.c` (CLAUDE.md, "To include/ has one
exception").

## What the C reproduces without being told

Everything round 13 managed by hand falls out of the compiler:

- **Load-delay nops** (`lbu; nop; sb`, `lw; nop; beqz`) — reorder-mode gas
  inserts them.
- **Delay-slot filling** — the `lui $2, 0x4` under `beqz`, the `addiu $2,
  $5, 0x24` under `blez`, the `sw $3, 0x30($5)` under the final `j` are gas
  hoisting the next independent instruction. The `ori $2, $zero, 1` under
  each culling branch is GCC placing the return value.
- **Block layout** — the `blez` failure path lands AFTER the success path
  (`2: ori $2,$zero,1` falling into the shared epilogue `3:`), and the other
  two failures jump straight to `3:` with `$v0` already set. That is GCC's
  ordinary layout for early returns with a common epilogue.
- **The `move $v0, $zero` hoisted above the `srav`** — GCC scheduling the
  return value early on the success path.
- **`$12`/`$13` as scratch in the flag test** — those ARE GPRs, and
  `gte_stflg` names exactly those two as clobbers. This is the one macro in
  `gte.h` with a GPR clobber; the store macros clobber only `"memory"`.

The flag check's shape — test zero first, then test `0x40000`, else fail —
is `if (flag) { if (flag != 0x40000) return 1; saturated = 1; }`. The mask
inside `gte_stflg` means `flag` can only ever be 0 or 0x40000, so the
`return 1` branch is unreachable in practice; the compiler cannot know that
and the game's author evidently did not either. Written as a `switch` or as
`else if` it might also match; the nested `if` was tried first and did.

## Two lessons that survive from round 13

The MECHANISM lessons from the whole-function version are still true and
still worth having; they are just no longer needed here:

1. **A hand-written `__asm__` containing a real branch mnemonic needs a
   tab-delimited `.set\tnoreorder` … `.set\treorder` bracket** or maspsx's
   defensive nop-after-branch pushes your delay-slot instruction out of the
   slot, and the unclosed state eats the nop off cc1's own epilogue. Now
   recorded in CLAUDE.md HARD RULE 6 and
   `docs/research/maspsx-noreorder-lead.md`. No macro in `gte.h` contains a
   branch, so nothing in `src/` needs the bracket today.
2. **Naming GPR clobbers on a COP2-only block cascades** through the
   surrounding allocation. `gte.h`'s store macros carry only `"memory"` for
   this reason.

The lesson that REPLACES round 13's conclusion: **"this instruction has no C
form" is a claim about an instruction; whether a FUNCTION has a C form is
decided by whether the SDK ships a macro for that instruction.** Every GTE
op does. See `docs/MATCHING-GUIDE.md` step 2 for the screen.
