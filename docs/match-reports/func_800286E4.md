CdSync == 5` case is:


retail's polarity there; only this function picks the opposite one, for
reasons this session could not pin down (see "What was tried" below).

### What was tried (all within budget, all rejected as non-byte-exact)

- `if (v1 != 5) goto L_end; newstate = 1; goto L_set;` (identical shape to
  `func_8002858C`'s matching case) -- `bne` polarity, wrong.
- `if (v1 == 5) { newstate = 1; goto L_set; } goto L_end;` (the textual
  mirror image) -- compiles to the byte-identical output as the `!=`
  version above; GCC normalizes both spellings the same way here.
- Splitting the `v1 == 5` success path into its own labeled block
  (`goto L_set5; ... L_set5: newstate = 1; goto L_set;`) reached via a
  `beq`-shaped test -- no change; still the `bne`-polarity encoding.

All three are semantically and structurally equivalent at the C level;
GCC 2.6.3 -O2's choice of branch polarity for this one comparison did not
respond to any of the rephrasings tried. The surrounding blocks (state 1,
the `v1 < 3` range check, state 7, state 8, and the shared `L_set`/`L_end`
tail) all match byte-for-byte with the same `goto`-dispatch technique that
closed `func_8002858C` outright, so this is not a wrong-idiom problem --
it is a one-instruction scheduling/optimization difference isolated to
this single comparison, possibly influenced by the `L_busy` block
(`newstate = 7; goto L_set;`, no function call) sitting where
`func_8002858C`'s equivalent `L_reset` block (`func_80028864(); goto
L_end;`, a real call) sits instead. Not tried: restructuring `L_busy` to
route through an extra dummy statement, or the permuter.

### Proposed learning

A `beq`/`bne`-only, same-length, single-instruction residue on an
otherwise-byte-exact function is not necessarily reachable by rephrasing
the *local* `if`/`goto` -- try varying nearby, unrelated blocks (here,
what the sibling branch target's body contains) before concluding the
construct itself is unmatchable, and record when several genuinely
different phrasings normalize to the identical encoding (worth knowing so
the next attempt doesn't re-try the same three spellings).
