## Derivation: a `New_X` allocator, and two failed shapes before the fix

A standard `New_X` allocator (pool-allocate 0x84 bytes, null-check,
construct through a shared ctor table) -- the "return-regardless" variant
per `docs/DECOMPILATION_LEARNINGS.md`'s `New_X` taxonomy (the constructor's
own return value is discarded).

- **First attempt (26/27):** `if (self != NULL) { ctor call; } return
  self;`. Structurally correct (one shared epilogue, right length) but one
  word off: retail's `beqz` delay slot materializes a FRESH `li $v0, 0`,
  where this form computes `addu $v0, $s0, $zero` (self, which happens to
  also be 0 on that path, but via a different instruction).
- **Second attempt (16/27, and everything past it shifted):** switched to
  two explicit `return` statements (`if (self == NULL) return NULL; ...
  return self;`). This DUPLICATED the epilogue -- two separate `lw
  ra/s0/s1/s2` + `jr ra` sequences -- which is the well-documented
  epilogue-merge hazard (`docs/research/epilogue-merge-residue.md`): GCC
  2.6.3 will not merge two exits carrying different literal return values
  into one epilogue on its own.
- **Fix:** the already-documented `goto`/`return` idiom for exactly this
  shape -- "an early exit returning a DIFFERENT value from the main path:
  with `goto fail; ... fail: return OTHER;` the exit value is stolen into
  the delay slot and the branch retargets to the epilogue" (round 8,
  `func_80025B34`). Writing the null path as `goto fail; ... fail: return
  NULL;` (rather than a bare early `return NULL;`) reproduced retail's
  single shared epilogue AND the freshly-materialized `0` in the branch's
  delay slot in one build.

### Proposed learning

**The already-documented `goto`/`return` lever for a New_X allocator's
null path is not just "an option that sometimes helps" -- for THIS shape
(constructor return discarded, single scalar return value, null and
success paths coincide on the same variable) it is required, and a bare
early `return NULL;` actively regresses to a worse (epilogue-duplicated)
state than not fixing the residue at all.** Worth flagging because the
26/27 near-miss looked like "one more tweak away" and the natural next
move (an explicit early return, the more idiomatic-looking C) made the
score six times worse before the documented lever recovered it.
