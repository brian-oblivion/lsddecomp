## Derivation notes

- `D_80010840` is a string symbol (`.asciz "none"`) in `asm/data/FD8.rodata.s`
  — referenced via `extern const char D_80010840[];`, never as a literal.
  Writing the literal `"none"` in C would emit a second copy in rodata and
  shift the whole image (the exact round-14/round-20 trap this unit's header
  comment calls out).
- `D_8006D620` is also read by `src/code_179d8_g.c` as `extern s32
  D_8006D620[4]` for a different, still-blocked accessor
  (`func_8002AEE0`). No shared header exists between the two units, so each
  file's own reading stands — this file's is `const char *[]` because the
  table entries are themselves addresses of strings in the same rodata
  block, and this function returns one of those addresses directly.
- **Branch polarity mattered and cost one round-trip.** The natural
  "guard-clause-last" phrasing —
  `if (sel < 0x1C) { return table[sel]; } return fallback;` — compiles to
  the RIGHT logic but the WRONG shape: GCC emits `bnez` on the in-range
  test and puts the fallback computation in the fall-through slot, i.e. the
  branch polarity and code layout are inverted vs. retail (which uses
  `beqz` to jump AWAY to the fallback, with the in-range table access as
  the fall-through). Flipping to the early-return-first idiom —
  `if (sel >= 0x1C) { return fallback; } return table[sel];` — reproduced
  retail's exact instruction order and byte pattern on the next attempt.
  Both C forms are semantically identical; only one matches the compiler's
  actual code layout.

### Proposed learning

For a two-way `if`/fallback shape where one arm is a literal/constant
return and the other is a table access, GCC 2.6.3 prefers the CONSTANT-
returning arm as the early-exit ("guard clause") branch, with the more
complex table-access arm as the un-branched fall-through — not the reverse.
Write the simple/constant case as the early `if (out_of_range) return
constant;` rather than trailing it after the "normal" case, even when both
read equally naturally in English.
