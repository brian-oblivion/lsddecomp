## What it is

A **hex-digit value function**. It masks its argument to a byte, reads a
character-classification table, and returns the digit's numeric value:

- table bit `0x4` set -> `c - 0x30` (`'0'` -> 0, so a decimal digit)
- table bits `0x3` set -> `(func_800133AC(c) & 0xFF) - 0x57` --
  `0x57` is 87, and `'a'` (97) - 87 = 10, so `func_800133AC` is a
  **`tolower`-like fold** and this is the `a`-`f`/`A`-`F` arm
- otherwise -> `0x98967F`, which is **9999999** -- the "not a digit" sentinel

## THE C (byte-exact)

```c
extern const u8 D_80066841[];
extern s32 func_800133AC(s32 c);

s32 func_80050AA4(s32 c) {
    u8 flags;

    c &= 0xFF;
    flags = D_80066841[c];
    if (flags & 4) {
        return c - 0x30;
    }
    if (!(flags & 3)) {
        return 0x98967F;
    }
    return (func_800133AC(c) & 0xFF) - 0x57;
}
```

## THE LEVER: invert the guard so the LONG arm is the fallthrough

The natural way to write this is with the sentinel last:

```c
    if (flags & 3) {
        return (func_800133AC(c) & 0xFF) - 0x57;   /* the long, call-bearing arm */
    }
    return 0x98967F;                               /* the short constant arm */
```

That is semantically identical and **compiles to a different layout**: GCC
2.6.3 inlines the SHORT constant arm as the fallthrough and branches to the
call-bearing arm, i.e. the opposite of retail. It came out `11/25` and **one
word SHORT**, because the inverted arrangement also let GCC fill the second
branch's delay slot, where retail has a bare `nop`.

**Writing the guard inverted -- sentinel first, call path as the fallthrough
-- produced retail's layout exactly and recovered the missing `nop` with it.**
Three variants measured, one line each:

| variant | result |
| --- | --- |
| sentinel last (`if (flags & 3) { call } return CONST;`) | 11/25, **1 word short**, arms laid out inverted |
| same, written as an explicit `else if`/`else` chain | 11/25 -- identical, so `else` is NOT the lever |
| same, with the call result in a named local first | 11/25 -- identical |
| **sentinel first (`if (!(flags & 3)) return CONST;` then fall through)** | **25/25, byte-exact** |

Note the second and third rows: the two things one instinctively reaches for
when arms come out swapped -- an explicit `else`, and breaking the expression
into a local -- both did **nothing**. Only the guard's polarity moved it.

## Open: the table's true extent, and its flag semantics

`D_80066841` is declared here **unbounded**, deliberately, and a future reader
should not "fix" that to a sized array:

- splat's `dlabel D_80066841` covers only **47 bytes** (`0x80066841` ..
  `0x80066870`), but this function indexes it with a full masked byte, 0..255.
  So the symbol is a **label INTO a larger table**, not the table itself.
- More telling: **none of the 47 visible bytes has bit `0x4` or bits `0x3`
  set.** They are `0x20`, `0x08`, `0x10` and `0x18` only. So every index this
  function actually cares about lies *past* the symbol's own extent --
  `'0'` is index 0x30 = 48, already one byte beyond it.

The table lives in `TodActor`'s data, whose tail CLAUDE.md's Gate 2 notes
already describe as "a character-classification table". The neighbouring
`sGameApplicationConfig` label is a candidate for the real base (`0x841 - 0x828` = 25).
**The flag-bit meanings are therefore NOT established** -- the `0x4` and `0x3`
readings above are inferred from this function's arithmetic (`- 0x30`,
`- 0x57`), which is solid, and not from any byte anyone has read. Resolving
the table's real base and bit assignment would be worth doing when
`TodActor`'s data is next touched, and would firm up several functions at
once rather than this one.

### Proposed learning

**When your arms come out swapped relative to retail, invert the GUARD, not
the structure.** GCC 2.6.3 chooses which arm falls through partly on arm
size/cost -- it will inline a two-instruction constant return and branch to a
call-bearing arm. Retail frequently does the reverse. Writing the source with
the *cheap* arm as an early-return guard and the *expensive* arm as the
fallthrough flips the layout to match. Two cheaper-looking fixes were measured
and are inert: adding an explicit `else`, and hoisting the arm's expression
into a named local. Both leave the layout exactly as it was.

**And a corollary worth its own line: this residue presented as "1 word
short", and the missing word was a `nop` in a delay slot the wrong layout let
GCC fill.** A one-word-short residue on a function with two arms is worth
testing for arm polarity before anything else -- the missing word may be a
delay-slot `nop` that only the correct layout leaves empty.
