## History: this was reported as a STALL, and the residue was misread

The first pass reached 32/33 with the identical body minus the last
argument, and the whole difference was retail's

```
/* 3A630 80049E30 1000A5AF */  sw  $a1, 0x10($sp)
```

in the prologue — a store to a slot the function never reads again, with the
frame 0x20 instead of 0x18. It was filed as an **unmotivated dead-argument
register spill**, a proposed new residue class, after a careful set of
eliminations: a plain unused parameter does not spill under this compiler at
-O2, an explicit dead local is deleted outright, a K&R definition changes
nothing, and the real header plus this body through the standalone pipeline
reproduces 32/33 exactly. All of those eliminations are correct.

They were aimed at the wrong question. **The store is not a spill. It is
argument setup.**

In the MIPS o32 ABI the first four arguments travel in `$a0`–`$a3` and the
**fifth and beyond are passed on the caller's stack starting at `0x10($sp)`**.
`sw $a1, 0x10($sp)` is `arg1` being placed as the fifth argument of the call
that follows; it appears up in the prologue only because `$a1` is about to be
overwritten by the second argument's own field load, so GCC stores it early.
"Never read again in this function" is exactly right and exactly what an
outgoing argument looks like from inside the caller.

## How to confirm it, and the general check

Read the CALLEE's frame arithmetic. `func_80052B70` (in `asm/class_3bb8c.s`):

```
/* 43370 80052B70 C8FFBD27 */  addiu  $sp, $sp, -0x38
...
/* 43398 80052B98 4800B58F */  lw     $s5, 0x48($sp)
```

`0x48 - 0x38 = 0x10` — it is reading the caller's fifth-argument slot. A load
from `(framesize + 0x10)($sp)` in a callee is a five-argument function, and
`0x10 + 4*(N-5)` generalises it to the Nth.

The declaration in the header said four arguments, so the call site could not
generate the store, and the entire function shifted by one word.

### Proposed learning

**An unexplained `sw $aN, 0x10($sp)` (or 0x14, 0x18, 0x1C) in a prologue, to a
slot never read again, is an outgoing stack argument — not a spill.** Before
theorising about the compiler, open the callee and check whether it loads from
`(its framesize + 0x10)($sp)`. If it does, your declaration of that callee is
one or more arguments short.

This is worth catching early for a second reason: the arity is wrong in the
HEADER, so every other call site in the project that reaches that function
inherits the same defect, and each one fails as an unrelated-looking
off-by-one-instruction stall in whichever unit it lives in.

Corollary for `m2c` users: `--sig` types the function you are decompiling, not
the ones it calls. A wrong arity on a callee is invisible to it.
