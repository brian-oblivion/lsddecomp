### Proposed learning

**The register-rescue heuristic these two siblings suggested ("rescue
whichever value is needed last") is too coarse.** `func_80031DF8`'s own
disassembly shows the LAST-stored value (`p1*129`) is never rescued at
all -- it is computed straight into the scratch register vacated by the
value that WAS rescued (`p2`). The real driver looks closer to "rescue
whichever incoming register is needed as a SCRATCH slot for an
intermediate computation before its own value is stored", which is a
narrower and more mechanical claim than "needed last" -- worth checking
against `func_80031CF0` directly (there, `p1` is rescued; is `p1`'s
original register, `$a1`, freed up and reused as scratch for the `idx*16`
stride computation before `p1`'s own store? If so, that is the same
mechanism under one description, not two different heuristics for two
siblings).
