### Proposed learning

**The "cache a global's address in a local pointer" lever is NOT uniformly
positive -- it depends on whether a CALL sits between the repeated
accesses.** `func_80054F30`'s and `func_8005511C`'s wins both cached a
value/address across a boundary the compiler otherwise couldn't prove safe
(a function call). Here, with no call between the three `D_8008E0AC`
accesses, introducing the same pattern made the build WORSE, not better --
suggesting GCC's own CSE should handle purely call-free repeated-global
access on its own, and when it visibly doesn't (as here), forcing it by
hand is fighting register-allocation pressure elsewhere in the function
rather than filling a gap the compiler couldn't see. Treat this as the
negative half of round 46's `func_80054F30` lever: scope it to values that
cross a CALL, not to same-block repeated access.
