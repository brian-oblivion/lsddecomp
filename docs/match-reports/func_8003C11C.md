# func_8003C11C

**Unit:** code_2c054 · **Size:** 48 instructions · **Status:** MATCHED (48/48 words)

## What it does

The base task class's own (unoverridden) implementation of method-table
slot `+0x040` -- the base-class counterpart to StreamTask's
`func_8003BA38`. Since StreamTask's own slot `+0x040` never chains down
to the base (func_8003BA38 does its five field-resets directly with no
`func_8003DFBC()` call), this function is only ever reached through a
BARE `BaseTask` instance, never through a `StreamTask`. Dispatches four
of its own (dynamically resolved, through `self->methods`) vtable slots
with a fixed rodata string split into three overlapping slices, then
resets eight of its own fields to fixed defaults.

## A real "cache the vtable pointer" residue

The first attempt read `self->methods` fresh at each of the four call
sites (`self->methods->slot6C(...)`, etc). That compiles to the RIGHT
overall structure but ONE WORD TOO MANY (49 vs 48): each fresh read
re-emits `lw $v0,0($s0)` (4 total), where retail loads `self->methods`
into a caller-saved register (`$s1`) exactly ONCE at function entry and
reuses it for all four dispatches -- 1 load instead of 4, at the cost of
one extra callee-save pair (`sw`/`lw` of `$s1`), netting one fewer
instruction overall. Introducing an explicit local
(`TaskBaseMethods *methods = self->methods;`) and dispatching through
`methods->slotXX(...)` reproduces this exactly.

### Proposed learning

When a function dispatches through the SAME object's vtable pointer more
than once, check whether retail caches that pointer in a saved register
(register `$s`N loaded once near entry, reused at every dispatch) before
writing `self->methods->slotXX(...)` at each call site individually --
GCC 2.6.3 will NOT hoist a repeated `self->methods` read into a register
on its own the way it does for a genuinely shared local. Confirmed twice
this pass (see also func_8003C3D0.md, same shape one function later:
`self->unk18->methods->slotXX(self->unk18)` called twice needed the same
fix). Worth checking on any slot-heavy dispatcher in this project before
spending attempts elsewhere.
