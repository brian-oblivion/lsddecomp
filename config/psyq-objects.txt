# Psy-Q library objects linked into the build, one per splat `o` segment.
#
#   <sdk version>  <lib>/<module>  <file offset of its .text in SLPS_015.56>
#
# tools/psyq_sdk.py install reads this, converts the matching disc in sdk/
# (bring your own -- see sdk/README.md), verifies each object's masked .text
# against retail at the offset, and writes lib/<lib>/<module>.o. The yaml's
# `o` segments must agree with this file: `tools/psyq_sdk.py check`.
#
# Which disc holds which build of a library is MEASURED by
# `tools/psyq_sdk.py match`, not assumed -- the game mixed library versions
# (libetc from the same build as the 3.5 disc, libgpu/libcd from an older one).

# psyq_2258 (0x2258..0x8220), converted chunk by chunk.
# Chunk A: the libapi heap allocator. `_obj/` is a loose .OBJ on the disc that
# is not a member of any .LIB. Its .sbss (0x20 at 0x8008AC28) and its 0x10
# .bss are placed by config/psyq-objects.ld, never in the yaml -- `place`
# reports `relocations DISAGREE` for the .bss precisely because Sony's linker
# scattered its two variables (0x8008E284 and 0x8008E888).
3.3  _obj/malloc    0x2258

# psyq_2258 chunk B (0x2F68..0x3C98): libc2 formatted output and string/ctype
# helpers, libgs matrix setup, two libapi BIOS stubs. Data sections:
# matrix .rdata 0x800 (0x30), prnt .rdata 0x830 (0x20C), prnt .sdata 0x7B010,
# ctype .data 0x57040 (the _ctype_ table, 0x81). prnt's .rdata is printf's
# format-dispatch jump tables, so its bytes are relocated words and `place`
# reports `bytes:not-found` -- the derived 0x830 lands exactly on the slot's
# existing dlabel D_80010030, which is the confirmation. matrix .bss and
# putchar .sbss go in the fragment.

3.3  libc2/bcopy    0x2F78

3.3  libc2/printf   0x3420
